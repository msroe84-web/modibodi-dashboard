# 모디보디 코리아 Business Dashboard — 전면 리뉴얼 설계

- 작성일: 2026-08-26
- 대상 저장소: `msroe84-web/modibodi-dashboard` (`index.html` 단일 파일, GitHub Pages 배포)
- 관련 문서: [BRAND.md](../../../BRAND.md) (모디보디 공식 아이덴티티 — 컬러/폰트/톤 참고)

## 1. 배경 및 목적

기존 6탭 구조(종합현황/매출/마케팅/CRM/분석/로드맵)와 Looker Studio 스타일 표·차트 디자인을
전면 폐기하고, 새로운 정보구조와 디자인 톤으로 다시 짠다. 대상 사용자는 총괄(대표에 준하는
포지션)이며 매일 아침 훑어보는 화면이므로 **정보 밀도보다 "한눈에 읽히는가"를 항상 우선**한다.

## 2. 절대 유지 사항

### 2-1. 일정관리(캘린더) 탭 — 완전 동결
HTML 구조, CSS 클래스(`.month-grid`, `.week-grid`, `.day-cell`, `.wk-slot`, `.modal`,
`.modal-side`, `.swatches` 등), JS 함수 일체(`dnum`, `dnumParts`, `dnumToISO`, `isoToDnum`,
`daysInMonth`, `firstWeekday`, `renderMonth`, `bindMoreLinks`, `showDayPopover`,
`closeDayPopoverOnce`, `closeDayPopover`, `bindEventBars`, `bindDayCells`, `highlightRange`,
`clearHighlight`, `renderSwatches`, `timeOptions`, `buildTimeDropdown`, `updateRangeHint`,
`openModal`, `closeModal`, `saveEvent`, `deleteEvent`, `renderWeek`, `setView`, `gotoMonth`,
`gotoWeek`, `renderReminders` — `index.html` 두 번째 `<script>` 블록, `const REAL_YEAR = 2026...`
부터 시작하는 영역)을 수정하지 않는다.

다른 탭에서 캘린더 데이터를 **읽어오는** 연동부(예: 로드맵 마일스톤 → 일정관리 자동 표시)는
새로 만들어도 된다. 캘린더 자체 로직만 건드리지 않으면 된다.

### 2-2. 글래스 디자인 토큰
```css
body {
  background:
    radial-gradient(60% 50% at 85% 8%, rgba(246,89,52,.16) 0%, transparent 70%),
    radial-gradient(50% 40% at 8% 92%, rgba(246,89,52,.10) 0%, transparent 70%),
    #050505;
}
.glass {
  background: rgba(255,255,255,.055);
  backdrop-filter: blur(22px);
  -webkit-backdrop-filter: blur(22px);
  border: 1px solid rgba(255,255,255,.14);
}
```
포인트 컬러 오렌지 `#F65934`는 모디보디 공식 브랜드 컬러와 동일하다([BRAND.md](../../../BRAND.md)
§5 컬러 팔레트 참고) — 그대로 유지. 새로 만드는 모든 위젯(KPI 카드, 표, 차트 컨테이너)에 동일
글래스 톤을 적용한다. `switchTab(id)` 함수와 `.tab-panel` / `.nav-item[data-tab]` 패턴도 유지한다.

### 2-3. 순수 HTML/CSS/JS 단일 파일 원칙
프레임워크·빌드 도구 없이 `index.html` 하나로 완결(더블클릭으로 열려야 함). 차트는 전부 직접
그린 SVG. 수정 완료 후 git add/commit/push까지 완료해야 GitHub Pages에 반영된다.

## 3. 버려도 되는 것

- 기존 `종합현황/매출/마케팅/CRM/분석/로드맵` 6탭 구조 자체
- 기존 표 디자인, KPI 카드 레이아웃, 도넛/트렌드 차트의 스타일 (구조는 참고 가능, 톤은 새로 정의)
- CSS 중복 선언 정리 (`.kpi4`, `.chart-tooltip2`, `.topbar-glass` 등 3~4회 중복 정의된 것들)

## 4. 새 정보구조 (IA)

| 탭 | 처리 |
|---|---|
| **전체 매출 현황** | 신설 (기존 종합현황+매출 통합 재설계, 로드맵 마일스톤 요약 흡수) |
| **마케팅** | 재설계 (핵심지표 + 소재분석 하위탭) |
| **CRM** | 콘텐츠 유지, 디자인만 교체 |
| **분석** | 콘텐츠 유지, 디자인만 교체 |
| **로드맵** | 별도 탭 폐지 — 콘텐츠는 "전체 매출 현황" 탭 하단에 컴팩트 카드로 흡수 |
| **일정관리** | 절대 수정 금지 (§2-1) |

로드맵을 별도 탭으로 두지 않고 흡수하는 이유: 총괄이 매일 훑어보는 탭이 "전체 매출 현황"이므로,
런칭 준비 마일스톤 진행률도 같은 화면에서 함께 보이는 편이 "한눈에 읽힌다"는 원칙에 부합한다.

## 5. 탭별 상세 요구사항

### 5-1. 전체 매출 현황 (신설 — 최우선 탭)

목적: 총괄이 이 탭 하나만 봐도 "지금 회사가 어떻게 돌아가는지" 파악 가능해야 함.

**필수 위젯 (위에서 아래 순서)**

1. **이번 달 목표 매출 진행률** (최상단, 가장 크게)
   - 데이터 소스: 구글시트 [`modibodi 2026 계획`](https://docs.google.com/spreadsheets/d/1EFsifOrig74WtYpErYsGruWYlp81zAVTTWI_CvqlHlE) 탭의 월별 매출 목표 행.
   - 참고 수치(2026년): 8월 0원 / 9월 593,250,000원 / 10월 640,200,000원 / 11월 686,500,000원 /
     12월 783,000,000원.
   - 진행률 = 해당 월 실적 매출 ÷ 목표 매출 × 100%. 실적 매출은 실제 판매 데이터(카페24 등)에서.
   - 시각화: 큰 숫자(진행률 %) + 프로그레스 바/게이지 + "목표 대비 ○억 부족/초과" 문구.

2. **채널별 매출 구성**
   - 자사몰(90%, 카페24) / 외부몰(10%, 29CM·무신사·W컨셉 등) / 인플루언서 공구(별도 트랙).
   - 인플루언서 공구는 마진 구조가 다름(인플루언서 40% : 리브위드 60% 배분) — 총매출에 섞지 않고
     별도 항목으로 명확히 구분.

3. **지출 내역 통합 뷰** (아코디언 또는 서브섹션 — 총액 요약 먼저, 클릭 시 세부 펼침)
   - 광고비 (META/NAVER SA/NAVER DA/KAKAO/GOOGLE/TIKTOK/리타겟팅 — 채널별 세분화)
   - 매입가(COGS) — 생리팬티/수영복/틴에이지 등 카테고리별 원가
   - 자사몰 PG사 수수료 (3.5%) / 외부몰 수수료 (20%) / 인플루언서 R/S (35%)
   - 물류비 (CJ택배 대행비 + 반품 2%)
   - 기타 고정비 (사이트 구축/관리, 부자재, GWP 제작, CS 대행, 촬영 등)

4. **영업손익(순이익) 요약**: 매출 합계 − 지출 합계, ROI(%) 함께 표시 (시트 참고치 ROI 19.3%).

5. **재고 현황 — 수기 입력 방식**
   - 카페24 재고 API 연동은 이번 범위에서 제외(연동 가능 상태 아님, §6 확인).
   - 품목별 재고 수량을 직접 입력할 수 있는 폼 위젯으로 시작, 로컬스토리지에 저장.
   - 나중에 API 연동 시 같은 위젯 자리에 실데이터만 꽂을 수 있도록, 위젯 자체는 "품목별 수량 +
     품절임박 강조 표시" 구조를 API 연동 버전과 동일하게 설계해 둔다.

6. **로드맵 마일스톤 요약** (기존 로드맵 탭 콘텐츠 흡수)
   - 런칭 준비 마일스톤 체크리스트(SSL/도메인 이슈, T1런 부스, 카카오 목표 등)를 컴팩트 카드로
     압축 — 전체 진행률 게이지 + 다음 마일스톤 2~3개만 노출, "더보기"로 전체 리스트 펼침.
   - 구조 변경 없이 기존 콘텐츠를 그대로 새 톤에 이식(§4 참고, 이번 라운드에서는 구조 재설계 안 함).

**데이터 원본 요약**: 구글시트 1개 파일 안에 "2026 계획"(월별 매출/지출 목표), "원가·판매가·마진율
관리"(품목별 원가/마진), "메가 인플루언서 공구 세트 구성표"(공구 전용 손익) 등 여러 섹션 —
실데이터 자동 반영 시 이 구조를 참고해 매핑.

### 5-2. 마케팅 (재설계)

**핵심지표 (상단, 기본 뷰)**: 아침마다 체크하는 용도이므로 최상단 배치. 메타/네이버/구글/틱톡/
리타겟팅 채널별로 광고비·매출·ROAS·CPA를 최근 기준(전일 또는 최근 7일) 스냅샷으로 표시. 채널
간 비교가 한눈에 되는 형태(막대/표 혼합 등).

**소재 분석 (하위 탭/서브 메뉴) — 이번 라운드는 UI 뼈대만**
- 기간 선택 필터 (최근 7일 / 30일 / 커스텀)
- 베스트/워스트 소재 랭킹 — 소재 썸네일, 소재명, 노출·클릭·CTR·CPA·ROAS를 정렬 가능한 표/카드로.
- 목업 데이터로 레이아웃만 검증. Meta 크리에이티브 레벨(ad-level) API 연동은 이번 범위 밖 —
  현재 Apps Script(`AppsScript_Code_v2.gs`)의 `syncMetaData`는 계정 레벨 광고비만 가져오는
  구조이며, ad-level 인사이트 확장 연동은 별도 작업으로 분리한다.

### 5-3. CRM (콘텐츠 유지, 디자인 교체)
유지 콘텐츠: 카카오톡 친구수(목표 1,000명), 총 회원수, 등급별 분포(Seed→Root→Bloom→Canopy→
Keeper), 카카오톡 친구수 추이, CRM 메시지 성과(알림톡/친구톡 전환율). 표/카드/차트 디자인만
§7 톤으로 교체.

### 5-4. 분석 (콘텐츠 유지, 디자인 교체)
유지 콘텐츠: 세션수, 평균 체류시간, 전환율, 이탈률, 노출/클릭/CTR/CPC/CPA, 디바이스별 세션 비중,
유입채널별 세션, 월별 세션 추이. 디자인만 §7 톤으로 교체.

### 5-5. 일정관리 — 손대지 않음 (§2-1 참고)

## 6. 확인 완료된 결정 사항

브레인스토밍 중 사용자 확인을 받아 확정됨:

1. **재고 데이터**: 카페24 API 연동 미가능 상태 → **수기 입력 방식**으로 시작 (§5-1-5).
2. **로드맵 탭**: 별도 탭 폐지, **"전체 매출 현황" 탭에 흡수** (§4, §5-1-6).
3. **소재 분석 데이터**: Meta 크리에이티브 API 연동은 **이번 범위 제외, UI 뼈대만** 구축 (§5-2).
4. **폰트 체계**: 한글 본문은 Noto Sans KR 유지 + **숫자 전용 IBM Plex Mono 추가 도입**. 작업 완료
   후 CLAUDE.md의 폰트 기재 내용(현재 Space Grotesk/Inter/IBM Plex Mono로 문서화되어 있으나 실제
   배포본은 Noto Sans KR만 사용 중이던 괴리)을 실제 상태에 맞게 갱신한다.

참고로 모디보디 공식 브랜드 폰트(Founders Grotesk, Items — [BRAND.md](../../../BRAND.md) §5)는
한글을 지원하지 않는 라틴 전용 서체이므로 대시보드 한글 UI 폰트 결정과는 무관하다.

## 7. 새 디자인 시스템 가이드

**유지**: 글래스 배경/블러/보더(§2-2), 오렌지 포인트 컬러(모디보디 공식 브랜드 컬러 `#F65934`와
동일 — [BRAND.md](../../../BRAND.md) §5).

**새로 설계**:
- 숫자 중심 위젯은 IBM Plex Mono로 통일해 자릿수가 흔들리지 않게 함 (§6-4).
- 색상은 최소한으로: 증감 표시(▲초록/▼빨강)만 색을 쓰고 나머지는 뉴트럴 톤. 데이터 스튜디오식
  다채로운 그라데이션 팔레트는 지양.
- 표는 zebra-stripe 대신 얇은 구분선 + 충분한 행간.
- 차트는 꼭 필요한 곳에만(막대/라인/도넛 최소화), 텍스트로 대체 가능한 정보는 텍스트로.
