# 모디보디 대시보드 리뉴얼 — 기반 구조 + Overview 탭 설계

## 배경 및 범위

기존 `index.html`(순수 HTML/CSS/JS, GitHub Pages 단일 파일 대시보드)을 완전히 새로운 스택으로
디자인/구성부터 새로 만든다. 이번 스펙은 전체 8개 탭 중 **기반 구조(레이아웃 셸, 디자인 토큰,
전역 상태, 공용 유틸) + Overview 탭**까지만 다룬다. 나머지 탭(마케팅/캠페인 캘린더/손익/CRM/
MD·상품/재고/설정)은 이후 각각 별도 스펙으로 순서대로 진행한다.

API 연동(Apps Script, Cafe24 등)은 이번 범위에 포함하지 않는다 — 지금은 Mock 데이터 단계이며,
실데이터 연동은 나중에 별도로 진행한다.

## 프로젝트 위치

`modibodi-dashboard/` 저장소 내부에 새 폴더 `web/`을 만들어 그 안에 Vite 프로젝트를 스캐폴딩한다.
기존 `index.html`은 손대지 않는다(현재 라이브 서비스 중). 배포 전환(GitHub Pages를 `web/dist`로
바꾸는 것)은 8개 탭이 모두 완성된 뒤 별도로 논의한다.

## 기술 스택

- Vite + React + TypeScript
- Tailwind v4 (`@tailwindcss/vite` 플러그인)
- Recharts (차트), lucide-react (아이콘)
- shadcn, Next.js 사용 안 함. 외부 이미지 소스(Unsplash 등) 사용 안 함
- 폰트: `@fontsource/noto-sans-kr` + `@fontsource/ibm-plex-mono` (npm 패키지로 로컬 self-host)
  - 브랜드 공식 폰트(Founders Grotesk, Items Condensed)는 영문 전용 유료 서체라 무료 npm 배포본이
    없고 한글도 지원하지 않아 제외 (사용자 확인 완료)
- 추가 비용 없음: 유료 폰트/외부 API/유료 호스팅·DB 미사용, 로컬 실행 기본

## 컬러 시스템

BRAND.md 공식 팔레트 기준, 사용자 확인 완료:

| 등급 | 색상 | Hex | 용도 |
|---|---|---|---|
| Primary (중요) | Orange | `#F65934` | 각 탭 헤드라인 숫자(매출 Hero, 목표 진행률 등)에만 사용. 버튼·탭 밑줄 등 면(채움)은 원색 그대로, 차트 얇은 라인/마크는 흰 배경 대비 확보를 위해 더 짙은 별도 톤(`#C7431F` 등, 구현 시 대비 검증 후 확정) 사용 |
| Secondary (덜중요) | Pink | `#ED429E` | 탭 자체 헤드라인이 아닌, 탭 내 덜 중요한 강조 요소 |
| Neutral (무난) | Grey | 기존 텍스트/배경 그레이 재사용 | 상태/정보성 배지 등. 새 토큰 만들지 않음 |
| Base | White + Grey | — | 배경 기본 |

- Primary/Secondary 각각 라이트/다크 모드용 톤을 별도로 정의한다.
- 구현 후 dataviz 스킬의 `validate_palette.js`로 명도 대비·CVD(색각이상) 구분성을 검증한다.
  검증 실패 시 톤을 조정한다. CVD 구분이 애매한 조합은 색상만으로 구분하지 않고 항상 라벨/색점을
  병기한다.
- 증감 지표(상승/하락)는 브랜드 컬러와 별개로 기존 관례대로 초록(`#4ADE80` 계열)/빨강(`#F87171`
  계열)을 사용한다(기존 라이브 대시보드와 톤 통일).
- 대비 검증에 실패한 색상(옐로 계열 등)은 데이터 강조 용도로 쓰지 않는다.

## 레이아웃 셸

- 좌측 고정 세로 사이드바: 상단 로고(`assets/logos/modibodi_*.png`, 라이트/다크에 맞는 버전 자동
  전환) + lucide-react 아이콘 기반 탭 네비게이션. 상단 가로 탭 방식은 쓰지 않는다.
- 접기/펼치기 토글: 너비 트랜지션. 접었을 때 라벨은 `overflow-hidden` + `max-width` 트랜지션으로
  사라진다.
- 다크/라이트 모드 수동 토글 버튼(사이드바 하단): 선택값을 `localStorage`에 저장하고, 수동 선택이
  항상 OS 설정보다 우선한다. 초기 로드 시 FOUC 방지용 인라인 스크립트를 `index.html` `<head>`에
  추가한다(React가 마운트되기 전에 `data-theme` 속성을 먼저 설정).
- 카드(StatTile류) hover 시 그림자가 진해지는 인터랙션. 라이트/다크 모드별 그림자 토큰을 분리한다.
- 카드 상단 아이콘 배지는 전부 Primary 오렌지 하나로 통일한다(카드마다 다른 색 쓰지 않음).
- 카드 메인 숫자는 값이 바뀔 때마다 이전 값→새 값으로 부드럽게 카운트업되는 애니메이션을 적용한다
  (커스텀 훅, 예: `useCountUp`).

## 전역 상태 & 공용 유틸

- `SettingsContext` (React Context + `localStorage`): 월 매출 목표, 재고, 판매가·원가, 수수료율,
  광고 예산을 관리한다. 이 값을 쓰는 모든 컴포넌트는 정적 import가 아니라 `useSettings()` 훅으로
  값을 받는다. Settings 탭(8번, 이후 스펙에서 구현)에서 값을 수정하면 이 Context를 통해 전체
  대시보드에 즉시 반영된다. 이번 스펙에서는 Context/Provider와 기본값만 구현하고, 수정 UI는 Settings
  탭 스펙에서 만든다.
- 공용 유틸(`src/lib/`): 숫자/통화 포맷터, 날짜 범위 필터·집계 함수. 탭마다 새로 만들지 않고
  공유해서 재사용한다.
  - 시계열 데이터는 전부 `{ date: string, value: number }[]` 구조로 통일한다.
  - 합계형 지표는 합산, 비율형 지표는 평균으로 집계한다.
  - 증감은 선택된 기간과 동일한 길이의 직전 구간과 비교해서 계산한다.

## Overview 탭

기존 라이브 대시보드의 실제 비즈니스 맥락(런칭 준비 단계, 채널: 자사몰(카페24)/외부몰(29CM 등)/
인플루언서 공구)을 이어받아 Mock 데이터를 현실감 있게 구성한다.

구성 요소(위에서 아래 순서):

1. **주의 필요 알림 위젯** (최상단): critical(재고 소진임박/예산 초과) / info(다가오는 일정) 배지.
   새 데이터를 만들지 않고 기존 데이터 조합만으로 구성한다. 이번 스펙에서는 캘린더 탭이 아직 없으므로
   critical 항목(재고 소진임박/예산 초과)만 재고 mock 데이터 + 마케팅 예산 mock 데이터로 구현하고,
   info(다가오는 일정) 항목은 이번 범위에서 제외한다. 캘린더 탭이 포팅되는 다음 스펙에서 info 항목을
   추가한다.
2. **날짜 범위 선택기** (우상단): 오늘 / 7일 / 30일 / 직접 지정. 선택에 따라 아래 모든 지표가
   필터링된다.
3. **매출 Hero + 월누적 매출**: Primary 오렌지로 강조된 헤드라인 숫자, 카운트업 애니메이션 적용.
4. **목표 진행률 카드**: `SettingsContext`의 월 매출 목표 대비 진행률.
5. **보조지표 카드들**: 광고비/ROAS/유입/전환/재구매/객단가/회원가입 등, 각 카드에 최근 7일
   스파크라인 포함.
6. **상품 순위 카드**: 상품별 매출 순위 (Classic/Seamfree/Swim/Teen 라인 기준 mock 데이터).
7. **채널별 매출 비중 카드**: 자사몰(카페24) / 외부몰(29CM 등) / 인플루언서 공구 구분.

## 캘린더 탭 (이번 스펙 범위 아님 — 방침만 기록)

3번 탭(캠페인 캘린더)은 이번 스펙에서 구현하지 않는다. 해당 탭의 별도 스펙을 작성할 때, 원 프롬프트의
"공구/프로모션/광고/입고" 신규 설계 대신 **기존 `index.html`의 "일정관리" 탭에서 로직과 데이터만
재사용**한다(사용자가 기존 캘린더 기능/데이터에 만족함을 확인) — 월/주 뷰 전환 방식, 이벤트 모달
인터랙션, 현재 이벤트 목록(회의/연차/캠페인 세팅/정산 등)을 그대로 유지한다.

**비주얼은 100% 새로 만든다.** 기존 `index.html`의 검정 배경 + 글래스모피즘 CSS는 전혀 가져오지
않고, 이번 스펙에서 정의한 디자인 토큰(Primary 오렌지/Secondary 핑크/Neutral 그레이, 카드 스타일,
라이트·다크 모드)을 그대로 적용해 다른 7개 탭과 톤을 통일한다. 구현 시 기존 `index.html`을 참고
자료로 한 번 확인하는 것 외에는 해당 파일에 의존하지 않는다.

## 테스트 / 검증

- `npm run dev`로 로컬 확인, 라이트/다크 모드 전환, 사이드바 접기/펼치기, 날짜 범위 선택기 동작을
  브라우저에서 직접 확인한다.
- `validate_palette.js`로 색상 대비/CVD 검증을 실행하고 결과를 스펙 또는 커밋 메시지에 남긴다.
- 반응형 레이아웃은 이번 범위에서 필수는 아니나(데스크톱 임원 보고용 우선), 극단적으로 좁은
  화면에서 깨지지 않는 정도는 확인한다.
